# Improvement Plan Specification

> Status: Verified against current codebase and implementation
> Source: improvement-plan source document in `docs/`

## Problem

The improvement plan contains audit findings, corrected assumptions, and prioritization data that are difficult to operationalize without a compact spec view.

## Goal

Consolidate verified findings, critical mismatches, and prioritized improvements into an implementation-oriented specification.

## Scope

### In Scope

- Audit-corrected project status and capability inventory
- Critical and architectural mismatches
- Prioritized improvement directions with rationale

### Out of Scope

- Rewriting historical decisions
- Expanding scope beyond documented audit conclusions

## Design Summary

- Source distinguishes already-implemented features from assumed gaps.
- Corrected executive summary becomes the baseline for future planning.
- Priority model is grounded in verified codebase reality.

## Success Criteria

- Improvement tasks reflect verified, not assumed, system state.
- Critical mismatches are visible and actionable.
- Planning decisions can reference one normalized spec artifact.
