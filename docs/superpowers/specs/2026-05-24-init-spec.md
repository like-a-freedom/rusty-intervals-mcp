# Intervals.icu MCP Core SPEC Specification

> Status: Verified against current codebase and implementation
> Source: `docs/SPEC.md`

## Problem

Core SRS/spec content is extensive; teams need a compact superpowers-indexed representation without losing key architecture decisions.

## Goal

Provide a concise specification of core MCP architecture, deterministic coach layer, intent behavior, and implementation module boundaries.

## Scope

### In Scope

- Core architecture and deterministic analytics model
- Intent behavior and API-first constraints
- Degraded-mode behavior and internal contract boundaries
- Implementation module mapping and rationale

### Out of Scope

- Detailed endpoint-by-endpoint API reference duplication
- Non-core roadmap items beyond current spec baseline

## Design Summary

- Source is the principal project-level SRS + tool reference artifact.
- Deterministic analytics and API-first discipline are central design tenets.
- Boundary definitions support maintainability and predictable evolution.

## Current Implementation Alignment

- Runtime entrypoint supports both STDIO and HTTP modes via `MCP_TRANSPORT`, matching current architecture docs and README.
- HTTP mode composes auth, `/mcp`, `/health`, and `/metrics` routes in one Axum app (`run_http_server`).
- Intent-first contract is preserved: 8 high-level intent tools are exposed; dynamic OpenAPI operations are runtime-internal.
- Dynamic registry loading is active and refreshed from configured OpenAPI source through the `dynamic` runtime subsystem.

## Success Criteria

- Core architectural intent is preserved in concise format.
- Deterministic and degraded-mode requirements remain explicit.
- Teams can use this spec as entry point before deep-diving into full source spec.
